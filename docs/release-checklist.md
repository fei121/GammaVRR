# Public Release Checklist

This checklist separates technical readiness from the legal authority to publish.

## Rights and provenance

- Confirm that you have the right to publish the algorithm and rewritten implementation.
- Confirm the chosen copyright holder text in `LICENSE`.
- Do not publish employer, customer, panel, or chip data without explicit permission.
- Use only the synthetic data generated by `examples/generate_example.py` in public examples.
- Review Git history, not only the current working tree. A new license at `HEAD` does not retroactively grant rights to historical files.
- If historical commits contain internal material, create a new public repository from the reviewed current tree with clean history. Do not rewrite or destroy this private repository's history without a separate backup and explicit approval.

## Technical verification

- Run Debug and Release builds.
- Run the complete test suite.
- Run the ASan/UBSan configuration.
- Build with `BUILD_SHARED_LIBS=ON`.
- Install the package and build `tests/install_consumer` with `find_package(GammaVRR)`.
- Generate fresh example data and run the CLI for P3 and P6 output.
- Verify that the CLI rejects a non-4095 PPM and an out-of-range FrameLevel.
- Confirm `git diff --check` is clean.
- Confirm the README and `docs/algorithm.md` match `src/model.cpp`.

## Repository presentation

- Rename the public repository from a generic internal name such as `Cmodel` to `GammaVRR` or `gammavrr`.
- Add a concise GitHub description and relevant topics such as `display`, `gamma`, `vrr`, `cpp`, and `rtl-verification`.
- Enable CI before tagging `v1.0.0`.
- Replace `Unreleased` in `CHANGELOG.md` with the actual release date.
